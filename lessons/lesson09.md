# 9강 · 오류 읽기와 디버깅

**목표:** 오류 메시지를 읽고, 문법 오류·실행 오류·논리 오류를 구분하며, 작은 입력과 중간값으로 원인을 찾아 수정한다.

이번 강의는 오류를 숨기지 않고 직접 재현하는 방식으로 진행한다. 오류가 발생하면 먼저 마지막 줄의 오류 종류와 오류가 발생한 코드 위치를 확인한다.

## 0. 디버깅이란?

디버깅은 프로그램이 기대한 대로 동작하지 않는 원인을 찾아 수정하는 과정이다.

다음 순서로 접근한다.

1. 기대한 결과를 문장으로 적는다.
2. 실제 결과와 오류 메시지를 확인한다.
3. 오류 종류와 발생 위치를 찾는다.
4. 입력·중간값·조건을 작은 예제로 확인한다.
5. 한 번에 한 부분만 수정한다.
6. 같은 입력과 경계 입력으로 다시 실행한다.

## 1. 문법 오류

문법 오류는 파이썬이 코드를 실행하기 전에 발견하는 오류다.

```python
if 10 > 5
    print("참")
```

콜론이 없으므로 실행 전에 `SyntaxError`가 발생한다.

```python
if 10 > 5:
    print("참")
```

들여쓰기 오류도 문법 오류에 해당할 수 있다.

```python
if True:
print("참")
```

조건문 안의 코드는 들여써야 한다.

## 2. 실행 오류와 traceback

문법이 맞아 실행은 시작했지만 실행 중 문제가 생기면 실행 오류가 발생한다.

```python
numbers = [10, 20]
print(numbers[2])
```

이 코드는 `IndexError`를 발생시킨다. 리스트의 유효한 인덱스는 0과 1이기 때문이다.

Traceback에서는 보통 다음을 확인한다.

- 오류가 발생한 파일
- 줄 번호
- 오류 종류
- 오류 메시지

오류 메시지의 마지막 줄부터 읽으면 원인을 빠르게 확인할 수 있다.

## 3. 자주 만나는 실행 오류

### `NameError`

정의하지 않은 이름을 사용하면 발생한다.

```python
print(total)
```

`total`을 먼저 대입하거나, 변수 이름의 철자를 확인한다.

### `TypeError`

자료형에 맞지 않는 연산을 하면 발생한다.

```python
age = "20"
print(age + 1)
```

문자열과 정수를 바로 더할 수 없다. 숫자로 사용할지 문자열로 사용할지 결정한 뒤 변환한다.

### `ValueError`

자료형은 맞지만 값의 형태가 잘못되면 발생한다.

```python
number = int("abc")
```

숫자로 변환할 수 있는 문자열인지 확인해야 한다.

### `KeyError`

딕셔너리에 없는 키를 대괄호로 조회하면 발생한다.

```python
scores = {"민수": 80}
print(scores["철수"])
```

`in`이나 `get()`으로 안전하게 조회한다.

### `ZeroDivisionError`

0으로 나누면 발생한다.

```python
average = total / len(numbers)
```

`numbers`가 빈 리스트일 수 있다면 먼저 길이를 확인한다.

## 4. 논리 오류

논리 오류는 프로그램이 실행되지만 결과가 기대와 다르게 나오는 경우다.

```python
numbers = [1, 2, 3]
total = 0

for number in numbers:
    total = number

print(total)
```

합계를 구하려면 `total = number`가 아니라 이전 값에 더해야 한다.

```python
total += number
```

논리 오류는 오류 메시지가 없을 수 있으므로 기대 결과와 중간값을 직접 비교해야 한다.

## 5. 중간값 출력하기

반복문 안에서 중간값을 출력하면 상태 변화를 확인할 수 있다.

```python
numbers = [3, 7, 2]
total = 0

for number in numbers:
    total += number
    print(f"number={number}, total={total}")
```

디버깅이 끝나면 확인용 `print()`는 제거하거나 필요한 로그만 남긴다.

## 6. `assert`로 예상 확인하기

`assert`는 조건이 참인지 확인한다. 조건이 거짓이면 오류를 발생시킨다.

```python
def add(a, b):
    return a + b

assert add(2, 3) == 5
```

함수가 기대한 결과를 반환하는지 작은 테스트를 만들 수 있다.

```python
def count_even(numbers):
    count = 0
    for number in numbers:
        if number % 2 == 0:
            count += 1
    return count

assert count_even([1, 2, 4]) == 2
assert count_even([]) == 0
```

## 7. 작은 입력으로 추적하기

복잡한 입력에서 문제가 발생하면 입력을 줄인다.

예를 들어 단어 빈도 함수가 이상하면 먼저 다음 입력을 사용한다.

```python
["a"]
["a", "a"]
["a", "b"]
[]
```

각 입력에서 딕셔너리의 상태가 어떻게 바뀌는지 적어 본다. 한 항목·중복·서로 다른 항목·빈 입력을 순서대로 확인하면 오류의 위치를 찾기 쉽다.

## 8. 함수의 오류 위치 찾기

함수는 입력·처리·반환을 분리해 확인한다.

```python
def average(numbers):
    if len(numbers) == 0:
        return None

    total = 0
    for number in numbers:
        total += number

    return total / len(numbers)
```

확인 순서:

1. 함수에 실제로 어떤 값이 전달되는가?
2. 반복문이 예상 횟수만큼 실행되는가?
3. `total`이 올바르게 누적되는가?
4. 나누는 값이 0이 아닌가?
5. 반환값을 호출한 곳에서 올바르게 사용하는가?

## 9. 자주 하는 디버깅 실수

### 오류 메시지를 읽지 않고 전체를 다시 작성함

먼저 오류 종류와 줄 번호를 확인한다. 전체 코드를 바꾸면 원인을 더 찾기 어려워진다.

### 여러 부분을 한꺼번에 수정함

한 번에 한 부분만 수정하고 다시 실행한다. 그래야 어떤 수정이 영향을 줬는지 알 수 있다.

### 변수 이름을 비슷하게 사용함

`score`, `scores`, `scroe`처럼 비슷한 이름을 섞지 않는다. 의미가 분명한 이름을 사용한다.

### 빈 입력을 테스트하지 않음

빈 리스트·빈 딕셔너리·빈 문자열을 반드시 확인한다.

### 디버깅용 출력만 보고 최종 결과를 확인하지 않음

중간값과 최종 반환값을 모두 확인한다.

## 10. 직접 작성하는 연습 문제

아래 문제는 오류를 직접 재현하고 원인을 설명한 뒤 수정한다. 각 문제에서 오류 종류 또는 논리 오류 여부를 기록한다.

### 문제 1 · 인덱스 오류

길이가 3인 리스트에서 잘못된 인덱스를 조회하는 코드를 작성하고 `IndexError`를 확인한다. 유효한 마지막 인덱스로 수정한다.

### 문제 2 · 자료형 오류

문자열 숫자와 정수를 더하는 코드를 작성해 `TypeError`를 확인한다. 문자열을 정수로 변환해 계산하도록 수정한다.

### 문제 3 · 키 오류

딕셔너리에 없는 키를 대괄호로 조회해 `KeyError`를 확인한다. `get()`을 사용해 오류 없이 기본값을 출력하도록 수정한다.

### 문제 4 · 빈 목록 평균

빈 리스트의 평균을 계산해 `ZeroDivisionError`를 확인한다. 빈 리스트이면 `None`을 반환하고, 그 외에는 평균을 반환하는 함수로 수정한다.

### 문제 5 · 잘못된 누적

합계를 구하는 반복문에서 누적 변수를 잘못 대입하도록 작성한다. 중간값을 출력해 오류를 찾고 `+=`를 사용해 수정한다.

### 문제 6 · 단어 빈도 테스트

단어 빈도 함수에 한 단어·중복 단어·서로 다른 단어·빈 리스트를 각각 전달한다. 각 결과를 예상한 뒤 `assert`로 확인한다.

### 문제 7 · 최댓값 경계

최댓값 함수에 양수 목록, 음수 목록, 한 항목 목록, 빈 목록을 전달한다. 빈 목록의 결과를 `None`으로 정하고 테스트한다.

### 문제 8 · 오류 설명

직접 만든 함수에서 발생한 오류 하나를 선택해 다음 네 문장으로 설명한다.

1. 어떤 입력에서 문제가 발생했는가?
2. 오류 종류는 무엇인가?
3. 어느 줄에서 문제가 발생했는가?
4. 어떻게 수정했고 어떤 입력으로 다시 확인했는가?

## 11. 오늘 배운 내용 확인

1. 문법 오류·실행 오류·논리 오류의 차이는 무엇인가?
2. traceback을 볼 때 마지막 줄에서 무엇을 확인하는가?
3. `IndexError`, `TypeError`, `ValueError`, `KeyError`, `ZeroDivisionError`는 각각 언제 발생하는가?
4. 중간값 출력은 논리 오류를 찾는 데 어떻게 도움이 되는가?
5. `assert`는 어떤 상황에서 사용하는가?
6. 왜 빈 입력과 한 항목 입력을 따로 테스트해야 하는가?

## 통과 기준

- 오류 메시지에서 오류 종류와 발생 줄을 찾는다.
- 문법·실행·논리 오류를 구분한다.
- 인덱스·형 변환·키·0으로 나누기 오류를 재현하고 수정한다.
- 중간값 출력이나 작은 입력으로 논리 오류를 찾는다.
- 수정 후 정상 입력과 경계 입력을 `assert` 또는 직접 실행으로 확인한다.
